# XGraph 产品需求文档

_X 账号关系采集与分析产品；PRD v0.1；2026-09-03_

---

## 📋 产品定位

XGraph 面向需要在 X 上寻找值得建立连接、合作或投放的账号的团队。用户提交一份 Seed List，系统沿每个 Seed 的 `following` 关系逐层采集，形成一片可查询、可筛选、可审计的账号关系网络，并为候选账号补充近期内容和互动表现。

XGraph 的首要产物是**可解释的关系数据**，不是自动触达工具。系统不代表用户自动关注、私信、投放或执行任何外部动作。

## 🎯 产品目标

### 首版目标

1. 从一份包含一个或多个账号的 Seed List 创建一次采集任务
2. 为每个 Seed 建立独立的 Root Tree，并沿 `following` 展开至 L5
3. 记录 L5 账号暴露出的 L6 账号作为边界节点，但不展开 L6
4. 在任务内去重账号、关系边和展开请求，同时保留重复发现路径
5. 保存账号基础资料、Following 关系和数据完整性状态
6. 对符合候选条件的账号采集最近 30 篇合格帖子及互动指标
7. 提供任务控制、进度查看、关系图、账号筛选、查询和导出
8. 任务可暂停、恢复，进程中断后不需要从头开始

### 非目标

- 不承诺获得 X 平台未向当前会话暴露的全部关系
- 不采集 protected 账号的非公开内容
- 不自动创建、购买或养号
- 不破解验证码、绕过安全检查或规避平台访问控制
- 不自动发送私信、关注、点赞或投放
- 不在浏览器一次性渲染百万级节点

## 👥 用户与使用场景

### 目标用户

内容运营、商务拓展、市场投放和研究人员。他们知道一组有价值的 X 账号，希望发现这些账号周围的共同关注、圈层核心和可触达对象。

### 典型流程

```text
准备 Seed List
    -> 导入并校验
    -> 创建采集任务
    -> 观察 L1 检查点
    -> 继续至 L5/L6
    -> 筛选候选账号
    -> 补充 Timeline
    -> 查看图谱、列表和详情
    -> 导出结果
```

## 🌳 任务与关系语义

### Seed List、Task 与 Tree

一份 Seed List 对应一次 Crawl Task。List 中的每个 Seed Account 是一棵独立 Root Tree 的根节点：

```text
Task T
├── Tree A: seed_a
├── Tree B: seed_b
└── Tree C: seed_c
```

多棵 Tree 共享同一个 Task 的资源和结果视图，但必须保留各自的根、路径和发现证据。一个账号在物理结果中只保存一份，账号被多个 Tree 发现时保留多条路径关系。

### 层级和边界

| 层级 | 定义 | 是否展开 `following` |
| --- | --- | :---: |
| L0 | Seed Account | 是 |
| L1 | L0 关注的账号 | 是 |
| L2 | L1 关注的账号 | 是 |
| L3 | L2 关注的账号 | 是 |
| L4 | L3 关注的账号 | 是 |
| L5 | L4 关注的账号 | 是 |
| L6 | L5 关注的账号 | 否 |

L5 是硬业务边界，但 L5 仍然要请求 Following 以产生 L6。L6 只保存当前响应已经暴露出的账号和 `L5 -> L6` 边，不创建新的展开任务。

### 重复和 collision

同一 Task 内发现已存在账号时：

- 账号节点只保存一份
- 已存在账号的 Following 不重复展开
- 实际观察到的关系边保留并去重
- 记录 collision、来源 Tree、来源账号、发现深度和时间
- 只结束当前重复分支，不停止其他分支或整个 Task

重复是圈层交集的重要信号，不等同于失败。

## 📊 账号与帖子数据

### 账号字段

每个进入 Task 的账号至少保存：

- X user ID、username、显示名和简介
- followers 数、following 数、认证状态和 protected 状态
- `can_dm` 触达状态（如当前响应提供）
- 首次发现层级、所属 Tree、发现时间和最后观测时间
- 声明 following 数、实际采集数、覆盖率和分页终止状态
- 数据来源、字段完整性和错误/部分状态

### 关系字段

每条关系边至少保存：

- source account ID
- target account ID
- Task ID、Tree ID、来源深度和目标深度
- 首次发现时间和最后观测时间
- 是否 collision、是否 L6 boundary

### 帖子字段

对进入画像队列的候选账号，最多保存最近 30 篇符合条件的帖子：

- 保留原创帖子和 Quote Post
- 排除纯 repost 和 reply
- 保存帖子 ID、作者、发布时间、正文和帖子类型
- 保存回复、转发、点赞、Quote、浏览和书签等可见指标
- 浏览量缺失时保留为空，不当作 0
- 不足 30 篇时记录真实样本数和时间跨度

账号聚合指标包括平均回复、平均转发、平均点赞、平均浏览、中位互动数、互动率、样本数、样本跨度和最近活跃时间。

## 🔍 候选筛选

候选筛选发生在关系采集结果之上，不决定 L0-L5 的基础遍历是否正确。首版可使用以下字段：

- `can_dm`
- followers 区间
- following 数和账号认证状态
- protected 状态
- 简介关键词
- 被多个 Seed 或多条路径发现的次数
- 网络内入度和局部圈层位置

筛选结果必须展示命中的条件和数据完整性警告。系统不得把启发式评分包装成确定性的“值得投放”结论。

## 🖥️ 浏览器功能

### 任务管理

- 粘贴账号或导入 CSV
- 预览规范化后的 Seed List
- 区分有效、无效、重复、停用和 protected Seed
- 创建、开始、暂停、继续和终止任务
- 查看当前层、每层进度、frontier、限流等待、失败和积压
- 查看关系图完成状态与 Timeline enrichment 状态

### 账号与关系查询

账号列表支持：

- username、显示名和简介搜索
- followers/following 区间筛选
- L0-L6 层级筛选
- Seed、Tree 和 collision 筛选
- `can_dm`、认证、protected 和数据完整性筛选
- 互动指标排序和分页

关系列表支持 source、target、Tree、depth、collision、L6 boundary 和时间筛选。

### 图谱

图谱默认展示受限子图，包括：

- Seed 周围的局部关系
- 指定账号的若干跳邻域
- 多个 Seed 的共同节点
- 候选账号周围的局部网络

节点应能够显示层级、Seed 路径、followers、`can_dm`、collision 和部分状态。图谱必须支持节点详情跳转，不要求一次渲染全量数据。

### 导出

至少支持 CSV 和 JSON：

- 账号列表
- 关系边列表
- 帖子与聚合指标
- 当前筛选条件、Task ID、生成时间和数据完整性状态

导出中的 X user ID 和 post ID 始终按字符串处理。

## ⏸️ 进度与状态

### 任务状态

```text
created -> validating -> running -> paused -> running
                         |              |
                         +-> failed    +-> terminated
                         +-> completed
```

任务页面必须区分：

- 尚未开始
- 正在采集
- 因用户暂停
- 因配额或运行保护等待
- 部分完成
- 失败但可恢复
- 关系图完成
- Timeline 仍在补充
- 完全完成

### L1 检查点

所有 Seed 的 L1 关系完成后，系统暂停并展示：

- 跨 Seed 的 L1 重叠率
- L1 followers 分布
- L1 `can_dm` 比例
- L1 声明 following 数分布
- 预计继续展开的规模和请求预算

第一版只展示指标，不自动判定 Seed 好坏。相互关注密度和 L1→L2 collision 需要继续展开 L1 后才能计算，不属于纯 L1 检查点。

## ✅ 产品验收标准

### 关系采集

- 一份 Seed List 只能创建一个明确的 Task 运行实例
- 每个 Seed 都能在结果中作为独立 Root Tree 查询
- L0-L5 的层级定义一致，L6 节点不再展开
- 同一 Task 内重复账号和关系边不重复存储
- collision 不会停止其他分支
- 任务中断后能从最后 checkpoint 继续
- 结果标注 partial、failed、collision 和 L6 boundary

### 账号画像

- Following 响应提供的基础账号字段可被查询
- 只有通过候选规则的账号进入 Timeline
- 纯 repost 和 reply 不进入合格帖子样本
- 每个账号最多保存 30 篇合格帖子
- 平均值、样本数和缺失浏览量可追溯

### 产品使用

- 用户可以导入、校验、开始、暂停、继续和终止任务
- 用户可以查询账号和关系并导出
- 用户可以打开受限关系图并查看节点详情
- 任务状态和数据质量警告与事实库一致
- Cookie、代理凭据和采集账号敏感信息不出现在页面、API 或导出

## ⚠️ 产品边界与风险提示

非官方 X Web 接口的可见范围由平台、会话和账号状态决定。XGraph 对外应使用“当前会话可观测到的关系采集”表述，并展示 declared/collected、分页终止原因和覆盖率，不能无条件宣传“完整关系图”。

采集账号是执行资源，不是图谱中的 Seed 或关系节点。账号池、限流、Kafka、PostgreSQL 和故障恢复属于技术实现，不应暴露为不稳定的用户调参项。
